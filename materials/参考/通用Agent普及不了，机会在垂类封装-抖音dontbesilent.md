## 一句话

通用 agent（Codex、WorkBuddy、云端个人助理）卖的是「什么都能干」，而新手要的是「明确告诉我你能干哪三件事」——这个落差就是垂类创业的全部空间：把通用 agent 大幅阉割，只把某一行业的高频需求流程化打通，交付渠道压到零学习成本（微信扫码），然后在工具之上接企业 FDE 改造。

## 核心论证链

### 1. 用户分层：真正的断点在 L3 到 L4

| 层 | 描述 | 规模判断 |
|---|---|---|
| L1 | 完全不用 AI | — |
| L2 | 偶尔和豆包聊天 | 最大存量 |
| L3 | 装了 agent 工具（Codex / WorkBuddy） | 安装量大 |
| L4 | **用好**：知道怎么搭知识库、构建上下文、用 skill / MCP / agent team | 极少 |

作者的关键判断：**L3 里 90% 以上只是「安装用户」，不是「用好」**。所以市场上的知识付费、企业咨询、培训，很大一部分业务就长在「L3 想变 L4」这道门槛上。

由此推出他的核心断言：**Codex 这类工具永远不可能普及，它必须靠培训和咨询行业推着走。**

### 2. 反驳「用户没需求」

常见的反驳是「大多数人根本不需要用 Codex 工作」。作者承认这半句，但拆开看：

> 用户对「用 Codex 工作」这件事没有需求，不等于对「Codex 能产出的成果」没有需求。
> 用 Codex 剪出华丽的视频特效，特效有没有需求？用 WorkBuddy 把公司财务打通，财务打通有没有需求？

需求在成果侧，不在过程侧。所以问题不是需求不存在，而是**成果和用户之间隔着一段用户走不过去的路**。

### 3. 归因：问题出在「通用」这个属性本身

他把两类产品归为同一物种：

- **桌面 agent**：Codex、WorkBuddy（装在本机）
- **云端 personal agent**：今年爆火的那几个（文稿转写为「girk boat」「mil se」，`[待核实]` 疑指 Manus 一类）

两类都叫**通用 agent**，共同缺陷有两个：

1. **场景模糊**——「我装了这玩意儿，我不知道它能干嘛」。啥都能干，对新手就等于啥都不能干。
2. **学习成本过高**——skill、MCP、agent team、上下文、知识库，这些概念得先搞明白，才能用出东西。

他给了一个对照：**新手需要的是「它有一二三几个功能，能做 PPT、能做表格」**，而不是一个能力面无限但无入口的黑箱。

### 4. 解法：做减法

两步，都不涉及模型能力：

- **场景收窄**：把某一类用户高频使用的功能一个一个拎清楚。以自媒体为例——提取别人文字稿、分析对标账号、把长素材剪成多条短视频。这些工具全部内置。
- **学习成本归零**：底层仍然是 agent skill 那套架构，但用户完全不需要了解；只用汉语对话就能解决；**微信扫码开箱即用**——「放到微信里，它有什么学习成本？」

他自己做的产品就是这个形态：在微信里做了一个完整的 AI 智能体。发一个抖音链接，它把视频文稿提取出来；发一篇短文说「这东西怎么拍成视频」，它直接返回一个把选题研究透的文件；再问「封面、标题、开头帮我写好」，也直接给。

### 5. 结论：这个形态在每一个行业都存在

> 各个行业都存在的垂类创业机会，就是把通用 agent 做一个大幅度的阉割，然后把少量垂类用户需要的需求全部流程化打通，让他们无痛使用。

严格的名字叫**细分行业的 AI 个人助理（personal agent）**，不是通用助手。

### 6. 变现：两条，第二条才是 FDE

有人问他：别人都在做 FDE（企业 AI 化改造），你怎么搓了个工具出来？他给的两条：

1. **卖复制**：我在创业 / 流量获客 / 自媒体这个领域把这个事跑通了，你想在你行业跑通，我把代码复制一份给你，你去干你的行业。
2. **工具即漏斗**：如果这个东西有大量人在持续续费使用，这些企业后续就有 AI 改造（FDE）需求。他找我，比找外面的人方便得多——**因为我直接把你手头这个工具给改造了**，不用重新做需求调研和系统接入。

第 2 条是他对「工具 vs FDE」这个质疑的正面回答：工具不是 FDE 的替代品，是 FDE 的前置获客层和数据层。

## 对学屿 / infinite 的判断

### 可直接借鉴的三条

**一、「阉割」不是产品缺陷，是降低采用成本的手段——这条给我们一个此前缺的论证角度。**

我们之前的论证都是 B2B 采购视角（机构买结果、买合规、买交付确定性）。这个视频补的是**终端使用者视角**：能力面越宽，采用门槛越高；门槛高到一定程度，产品就必须靠培训和咨询去推，规模上不去。

这和我们已有的两条设计决定是同一个方向，只是当时没意识到它同时是市场策略：
- §12.4 的 **Capabilities / Tools 二分**（固定流程写成 capability，工具只做可插拔件）
- v3 contract pack 的 **「固定 workflow 用显式 LangGraph，禁止自由 swarm」**

**二、交付渠道本身就是产品设计，不是分发渠道。**

「微信扫码开箱即用」在这个论证里不是运营手段，而是**学习成本的一部分**：装在哪儿、要不要注册、要不要配 key，全部计入用户的采用成本。这与我们 §12 里判断的「IM 通道优先（学生与家长本来就在微信里）」是同一个结论，但理由更硬——不是「用户懒得装 App」，而是「安装动作本身就是一道筛掉 90% 用户的墙」。

**三、轻工具 → 企业 FDE 的漏斗，对学屿是可执行的商业路径。**

我们同时在跑两条线：infinite（产品）和学屿的 FDE 咨询/交付业务。这个视频给了一个把两条线接起来的结构：
- 单点工具（如「文书诊断」「选校评分」「材料核查」）做成零门槛入口，微信/网页即用，不要求机构先上系统；
- 工具用起来之后，机构自然产生流程改造需求，而改造对象就是它已经在用的那个工具——比从零做需求调研的 FDE 项目省一整个前期阶段；
- 工具侧的使用数据同时是改造时的现成证据（哪些环节真的在用、卡在哪）。

这比「先卖 OS 再卖咨询」或「先做咨询再沉淀产品」都轻，而且两条线互为证据。

### 两条边界：不能照搬的地方

**一、他的对象是个体户，我们的对象是机构，流程复杂度不在一个量级。**

自媒体单人的高频需求就那么几件，阉割到五六个功能仍然够用。机构的招生—申请—文书—签证—合同—收款是一条长链，且每个机构的 SOP 不同。**过度阉割会把它退化成「只能做一件事的 SaaS」，反而丢掉 OS 的价值**。

正确的取法不是做两套产品，而是**同一套 capability 体系、两种表面**：
- 轻表面：单点、零学习成本、微信即用（拿来做获客和个体顾问）；
- 重表面：编排、审批、多人协作、审计（拿来做机构交付）。

底层是同一套 capability / tool 定义和同一套 run 生命周期，只是入口和暴露的能力面不同。这样做的好处是轻表面的使用数据能直接喂给重表面的评测与改造。

**二、「Codex 永远普及不了」对通用工具成立，对垂类封装不成立——别把这个断言用错地方。**

他的推论前提是「工具的价值必须由用户自己组装」。一旦把组装工作前置到产品里（预置 capability、预置知识库、预置行业工具），这个前提就不成立了。所以这条断言的正确读法是：**通用 harness 的普及天花板是「会用的人有多少」，垂类封装的普及天花板是「这个行业有多少人」**——后者高一个量级。这不是「AI 工具不行」，恰恰是「AI 工具的机会在封装层」。

### 一个需要警惕的地方

他的产品能卖，靠的是他自己在自媒体/流量获客这个领域的**方法论已经跑通**（选题怎么研究、封面标题开头怎么写、长素材怎么切片）。工具只是把方法论固化了。

对应到我们：**阉割的前提是先有一个被验证过的流程**。如果某个 capability 我们自己都说不清「好」的标准是什么，封装出来的只会是一个更窄的通用 agent，不会更好用。所以做减法的顺序应该是：先定确定性规则和验收标准（这正好接上 §12.4 的「确定性评分 + 档位约束」），再封装成 capability，最后才谈零门槛入口。

## 原文（校准版）

> 语音转写原文保留，仅修正明显同音错字并标注。`[转写]` 表示原词不可辨或疑为误转。

在微信里面做了一个完整的 AI 智能体。我现在把抖音链接发过去，它可以把视频文稿给我；我发过去一个短文，我说这东西怎么能拍成视频呢？它会直接返给我一个文件，把这个选题彻底研究清楚。那我说你能不能把封面、标题还有开头都给我写好呢？这个截图里面的效果大家可以自己看。

这是我最近在做的一个产品。因为我发现，即便是到了 2026 年，现在 AI 个人助理的产品可以说是井喷了，我觉得依然存在非常大的做垂类 agent 的创业机会。

说完这个估计很多人想喷我，因为你说现在做 agent 的都是腾讯、字节、OpenAI 这种上市公司级别的，我这团队才几个人。但你先别着急喷我，因为现在的情况是：我截图的这个东西，我现在还没正式开售，想买的人已经排上队了，我都交付不过来。

所以今天这个视频想跟大家聊一下：现在 AI agent 这个市场格局是个什么样？为什么我说还存在大量的中小创业者的创业机会？以及为什么这些顾客他要放着 WorkBuddy、Codex 不用，他得用我这个。

想看清市场，我们要先给用户分个层：
- 最底下一层是完全不用 AI 的；
- 第二层是偶尔和豆包聊聊天的；
- 第三、第四层是我们所谓的 AI agent 智能体用户，比如他安装了 Codex 或者 WorkBuddy。

但是这里面百分之九十九 `[转写]` 人他只是安装用户，他不是「用好」这个东西。「用好」指的是你明确知道怎么搭建知识库、怎么构建上下文、用好 skill、MCP，这个叫用好。

那我在这里发现的机会是什么？就是第二层和第三层的用户想成为第四层的用户，这里面的门槛实在是太高。

我们现在所看见的所谓割韭菜的也好、所谓良性的交付也好，这些知识付费和企业咨询，很大一部分业务都来源于这个。包括像 Codex 和 WorkBuddy 这种需要靠培训和咨询行业去推动的工具——它永远都不可能普及。

那有人说用户没需求，说大多数用户根本就不需要使用 Codex 去工作。我说对，你说的没错，但是他只是对「使用 Codex 工作」这件事情没有需求，他不是对「Codex 的工作成果」没有需求。

你今天用 Codex 剪了一个华丽的特效，它的特效有没有需求？你明天用 WorkBuddy 把公司财务打通了，这个财务打通有没有需求？它太有需求了。

那为什么他有这个需求，他却用不起来呢？根本原因就是：无论是 Codex、WorkBuddy 这种装在你本地电脑上所谓的桌面 agent，还是今年爆火的、放在别人云端的所谓个人助理 personal agent，**他们两类都叫通用 agent**。

那么问题来了，你身边能把这些产品都用明白的人有几个？所谓通用 agent，它就啥都能干。那我说难听点，对于新手而言，啥都能干就等于啥都不能干。一定是你明确地告诉我：它有一二三几个功能，它能做 PPT、它能做表格，新手才有可能把它用得上。

所以通用 agent 带来两个情况：
第一，我安装了这玩意儿，我不知道它能干嘛，这个叫**场景模糊**。
第二，这玩意儿你真要把它学明白，学习成本太高了——skill、MCP、什么 agent team 都要搞清楚，学习成本过于高昂。

那怎么办？做减法。

第一个，场景收窄：把你高频使用的功能一个一个都拎清楚。比如说做自媒体的，你是不是想提取别人的文字稿？是不是想分析对标？是不是想把你一个长素材剪成多个短视频？好，这些工具全部内置。底层依然是 agent skill 那套架构，但是你完全不需要了解这些，你就用你的汉语去对话，全都能给你解决掉。微信扫码，开箱即用。

第二个，学习成本：放到微信里边，它有什么学习成本？

这就是我说的、在各个行业都存在的垂类创业机会——**把通用 agent 做一个大幅度的阉割，然后把少量的、你的垂类用户需要的这些需求全部流程化打通，让他们无痛地使用。**

严格讲，这个东西全名叫做「细分行业的 AI 个人助理」（personal agent）。

那最后说一下这个事儿还能怎么挣钱。有人问：别人不都在做 FDE 吗？企业 AI 化改造，怎么你搓了个工具出来呀？

第一，我在创业、流量获客、自媒体这个领域把这个事给跑通了，那如果你想在你的行业里面跑通，我是不是可以把我的代码直接复制一份给你，去干你的行业。

第二，如果这个东西后续有大量的人在持续续费使用的话，那么这些企业有这个 AI 改造（FDE）的需求，他找我，是不是相比找外人要方便得多得多？因为我直接把你手头这个工具给改造了呀——这企业定制啊。

那这两个事情它叫不叫 FDE？叫。
