# knowledge · 核心知识库

团队唯一的知识沉淀目录。所有清洗产出的结构化知识条目都放这里，**用 frontmatter 的 `layer` 字段区分 Akasha 三层**，不再拆子目录。

## 三层标签（Akasha 记忆模型）

| layer | 存什么 | 例子 |
|-------|--------|------|
| `facts` | 发生了什么——文档、会议、代码、工单、交付物 | 某次客户会议纪要、某份已交付的需求书 |
| `interactions` | 为什么重要——决策、分歧、权衡、假设、推理链 | "为什么选方案 A 不选 B"、报价底线取舍 |
| `actions` | 下一步做什么——SOP、工作流、技能雏形、护栏偏好 | 标准回复模板、精排 Word 导出流水线、"客户文档不带版本号" |

## 文件规则

- 知识条目：`主题关键词.md`，用 `_templates/knowledge-entry.md` 格式。
- 周报：`YYYY-Www.md`（如 `2026-W34.md`），聚合本周所有条目摘要 + 待固化候选。
- **金额不脱敏**：涉及报价、费用时直接写明具体数字，不要替换成"详见源文件"。原因：多数条目是可直接执行的模板、话术与检查清单，脱敏会让它没法直接用。（2026-08-29 明确，覆盖此前部分条目的脱敏写法。）

## 为什么不分目录

事实 / 交互 / 行动是**分类法**，不是**文件夹**。小团队起步，目录越少：
- 投递时不用纠结归哪类；
- Agent 检索时少跳一层，命中更快；
- 一条知识跨三类时（既是事实又含决策），一个标签就够了。
